# v0.3.32

macOS 和 Windows 移除 Dodex 桌面双开，只保留官方 Codex App。设置中的
**TUI 双开**提供 Dodex TUI 安装、修复及两套 TUI 的独立监控与更新。两套 TUI 使用
独立账号、程序包、历史、数据库、日志、原生 daemon 和更新目录，版本可以不同。

`dodex update` 更新自身的完整官方 standalone 包；`dodex app` 提示不再支持。
`agent-companion dodex-tui --install/--repair` 接入已有副账号目录和历史，保留
原有配置，不复制主账号认证。点击 Dodex 任务会打开或恢复终端会话，显式配置同步
与账号接力继续可用。

迁移按归属校验处理旧 Dodex 桌面启动器和快捷方式，保留恢复副本，并持续刷新已登记
的旧 PATH 命令。主 Codex 保留原有 npm、Homebrew 或其他安装渠道；npm 安装的
原生 TUI 也可用于账号接力与会话恢复。

启动 Dodex 时检查命名 profile 和受信任项目配置中的账号存储设置，防止数据库、
日志或认证存储切回其他账号。模型和 MCP 配置保留原生行为；等价的 Windows 目录
写法可直接迁移，已有有效配置无需重写。

本次还修复从 PowerShell 7 环境启动 Companion 后，Windows TUI 安装、修复或
程序包校验可能因 `Microsoft.PowerShell.Security` 无法加载而失败的问题。
维护用 Windows PowerShell 子进程明确指定匹配的模块根目录；打开 TUI 时保留用户
原有的模块路径。官方包中的 `codex.exe` 和 `codex-code-mode-host.exe` 继续要求
有效的 Authenticode 签名及 OpenAI 签名者。

The desktop mirror is removed on macOS and Windows. Codex and Dodex are now
independent native TUIs with separate accounts, packages, histories, storage,
daemons and updates. Settings provides installation, repair and independent
update actions; Dodex task navigation opens or resumes a terminal session.
Existing secondary data is retained, and the primary keeps its installation
channel. Explicit config sync and account handoff remain available.

Migration refreshes verified Companion-owned commands and retires owned desktop
entries with recovery copies. Native npm session recovery, named-profile and
trusted-project storage validation, and equivalent Windows path spellings are
supported.

Windows maintenance commands also load the matching built-in PowerShell modules
when Companion inherits a PowerShell 7 environment. Terminal launch retains the
caller's module path, and both native executables still require valid OpenAI
Authenticode signatures.

The module-loading failure was reproduced locally, and the same native binary
passed the signature check with the built-in module path. v0.3.32 CI, release
archive verification and local TUI repair are pending at this documentation
stage. v0.3.31 remained a draft; its source and candidate validation results are
recorded separately in
[validation](../VALIDATION.md) and the
[Windows verification record](../WINDOWS_VALIDATION.md).

See [TUI installation, migration and recovery](../macos-dual-instance.md).
