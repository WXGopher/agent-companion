# v0.3.35

本版汇总自 v0.3.34 以来的 Windows 任务、通知、屏幕选择和 Companion 更新改进。

- **提问与审批通知**：Codex 或 Dodex TUI 等待回答或工具审批时发送静音 Windows 通知，3 秒后收起；同一问题不会重复提醒。通知与账号分别归属，回答或结束等待后撤下。点击后优先返回已记录的 Windows Terminal 标签页与分屏；普通 TUI 只有在问题文本唯一匹配可读取的 pane 时才切换。无法确认位置时保留任务面板。可在设置中单独关闭这类通知。
- **双账号活动归属**：分别检查各 `CODEX_HOME` 的历史记录与当前写入者。复制或导入的另一账号历史不会再让 Codex 和 Dodex 同时显示同一个正在运行的任务；在本账号真正恢复的会话继续正常跟踪。
- **不活动任务清理**：默认保留最后活动后 5 小时的任务记录，可在 **Settings → Taskbar & app** 调整为 1–168 小时。Tasks 页的 **Clear inactive** 立即清理不活动记录；当前写入中的任务和仍在等待回答的会话受到保护。没有活动证据的安静会话在现有 15 分钟窗口后进入 Finished，标为 Inactive。清理状态跨重启保存，重复扫描不会恢复旧记录，新活动可使会话重新出现。此操作只清理 Companion 的列表历史。
- **任务栏屏幕选择**：默认跟随 Windows 主屏，也可在设置中指定已连接的屏幕，立即生效并保存。指定屏幕断开或没有可用任务栏时暂用主屏，恢复后自动切回；保存的屏幕身份不受显示编号或窗口句柄变化影响。
- **Companion 一键更新**：公开 Windows x64 版本检测到较新稳定版后，可在主面板点击 **一键更新**，下载官方 Windows ZIP、校验 SHA-256、替换当前解压目录的发布文件并重启。面板显示下载、校验、准备和重启状态，关闭面板后下载继续；失败后可查看完整错误并重试。报告的替换或启动失败会回滚。此操作不更新 Codex 或 Dodex TUI，也不改写它们的账号与配置。突然断电或进程硬崩溃仍可能需要依据保留的事务记录与备份手动恢复。

本地默认构建继续显示 `100.0`，不检查 Companion 发布、不展示缓存的更新提示，
也不启用一键更新。macOS 继续通过发布页链接升级；本版没有增加 macOS 自动安装。

This release collects the Windows task, notification, display and Companion
update changes since v0.3.34.

- **Question and approval notifications:** Codex and Dodex TUI waits trigger silent Windows notifications that collapse after three seconds. Each request is notified once, stays with its account and is withdrawn when resolved. Clicking prefers the recorded Windows Terminal tab and pane. For ordinary TUIs, navigation requires a unique question-text match in a readable pane; otherwise the Tasks panel stays available. These notifications have their own setting.
- **Independent activity ownership:** history and current writers are checked against each `CODEX_HOME`. Copied or imported history from the other account no longer makes both Codex and Dodex count the same running task. Sessions actually resumed by the monitored account remain tracked.
- **Inactive task cleanup:** retain task history for 5 hours after last activity by default, configurable from 1–168 hours in **Settings → Taskbar & app**. **Clear inactive** removes eligible records immediately while protecting current writers and live waiting requests. Quiet sessions without current activity evidence move to Finished as Inactive after the existing 15-minute window. Dismissal survives restarts and repeated scans; new activity can revive a session. Cleanup affects Companion's list history only.
- **Taskbar display selection:** follow the Windows primary display by default or select a connected display in Settings. Changes apply and save immediately. If the selected display or its taskbar is unavailable, the readout temporarily uses the primary display and returns when possible. The saved monitor identity survives display-number and window-handle changes.
- **One-click Companion updates:** after detecting a newer stable release, published Windows x64 builds offer **一键更新** (One-click update) in the main panel. The app downloads the official Windows ZIP, verifies SHA-256, replaces release files in the current extracted installation and restarts. Progress remains visible, downloads continue with the panel closed, and failures expose complete details and retry. Reported replacement or startup failures roll back. Codex/Dodex TUIs, accounts and settings remain separate. A power loss or hard crash can still require manual recovery using the retained transaction records and backups.

Default local builds continue to show `100.0`, disable Companion release checks
and cached update notices, and do not enable one-click installation. macOS keeps
its release-page update link; this release does not add automatic macOS installation.

Development Windows regressions, UI input and render checks are recorded in the
[Windows validation record](../WINDOWS_VALIDATION.md). That document distinguishes
completed checks from pending notification/focus, physical display hot-plug and
published-package updater acceptance. Final merged CI, package verification and
provenance will be recorded after the release workflow completes.
