# Agent Companion v0.3.26

- **macOS 登录时自动启动**：设置新增“通用”页，集中管理额度自动刷新间隔和“登录时自动启动”。使用系统原生登录项，在当前用户登录时启动菜单栏应用；关闭只取消后续自动启动，当前应用继续运行。
- **系统状态与操作反馈**：开关直接读取 macOS 实际状态，并在设置窗口打开期间持续刷新。等待批准、系统撤回许可或操作失败时显示原因，提供“系统登录项设置”和取消待批准注册的入口。首次尚未注册显示为正常关闭状态，开发目录中的裸二进制不会注册登录项。
- **设置开关同步**：修复开关双向绑定，确保操作失败后回到真实状态，外部状态变化也能及时显示。

本地原生登录项测试、37 阶段隔离设置窗口测试、全目标 Clippy 和格式检查通过。已安装的 ad-hoc 签名开发包完成真实开启、关闭、再次开启；设置进程重启后仍读取已开启状态，系统记录确认登录项已开启并获准，指向已安装的 App。**完整注销／重新登录、重启后的自动启动和 Windows GUI 尚未实机验证。** 详见[菜单栏与验证记录](https://github.com/WXGopher/agent-companion/blob/v0.3.26/docs/MACOS_MENU_BAR.md)。

macOS 包适用于 macOS 14+ Apple Silicon，使用 ad-hoc 完整性签名，未做 Apple 公证。

## English

- **macOS launch at login.** Add a General tab (通用) for the quota refresh interval and launch at login. The native login item starts the menu-bar app when the current user signs in. Disabling it cancels future automatic launches and leaves the running app open.
- **System state and feedback.** Read the actual macOS state and refresh it while Settings is open. Pending approval, revoked permission and operation failures show a reason, with access to System Settings and cancellation of a pending registration. An app with no registered login item starts in a normal off state; an unbundled development executable cannot register itself.
- **Settings switch synchronization.** Fix two-way switch bindings so failed operations restore the actual state and external changes appear in Settings.

Local native login-item tests, the 37-phase isolated Settings editor, all-target Clippy and formatting checks passed. An installed development bundle with an ad-hoc signature passed real enabling, disabling and re-enabling checks. Restarting Settings retained the enabled system state, and system records confirmed an enabled, allowed login item pointing to the installed App. **A full logout/login cycle, automatic launch after a restart and Windows GUI remain unverified.** See the [menu-bar guide and validation record](https://github.com/WXGopher/agent-companion/blob/v0.3.26/docs/MACOS_MENU_BAR.md).

The macOS package requires macOS 14+ on Apple Silicon and uses an ad-hoc integrity signature without Apple notarization.
