# v0.3.31

桌面双开已移除，macOS 和 Windows 只保留官方 Codex App。设置中的 **TUI 双开**
独立安装、修复、监控和更新 Codex TUI / Dodex TUI，两套版本可以不同。

`dodex update` 直接更新自身的完整官方 standalone 包，默认使用原生 daemon；
`dodex app` 明确提示不再支持。新入口 `agent-companion dodex-tui --install/--repair`
接入已有副账号目录、历史、数据库和日志，不复制主账号认证，也不强制结束终端。

Windows 迁移会更新已登记的旧 PATH 命令，并在重复修复时继续更新这些入口；
旧 Dodex 桌面启动器及开始菜单快捷方式按归属校验后备份移除。主 Codex
保留原有 npm 或其他安装渠道，npm 安装的原生 TUI 也可用于账号接力与会话恢复。

启动 Dodex 时会检查命名 profile 和受信任项目配置中的账号存储设置，防止这些
原生配置层把数据库、日志或认证存储切回其他账号；模型和 MCP 等配置保留原生行为。
等价的 Windows 目录写法可直接迁移，已有有效配置无需重写。

The desktop mirror and paired updates are removed. The two TUIs own separate
accounts, packages, daemons and update directories. Codex retains its original
installation channel. Settings shows two independently updateable TUI rows;
Dodex task navigation opens or resumes a terminal session. Explicit config sync
and account handoff remain available.

Windows migration refreshes registered legacy PATH commands on every repair
and retires only verified Companion-owned desktop entries with recovery copies.
Primary npm installations retain their command precedence and native session
recovery support.

Dodex launch validates account storage in named profiles and trusted project
configuration layers while preserving native model and MCP settings. Equivalent
Windows directory spellings migrate without rewriting valid existing profiles.

See [TUI installation, migration and recovery](../macos-dual-instance.md).
Native macOS / Windows builds, real-package acceptance and the local deployment
are recorded in [validation](../VALIDATION.md) and the
[Windows verification record](../WINDOWS_VALIDATION.md).
