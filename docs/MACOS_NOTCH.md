# macOS Codex 刘海

## 本轮范围

- 默认启动窄刘海；展开后的齿轮 **Settings（设置）** 打开 TUI 定制窗口，关闭设置后刘海继续运行。`agent-companion codex-tui` 仍可直接打开设置。
- 弹出面板与收起时同宽，只向下展开。MacBook 上周剩余额度在摄像头左侧，工作数与待处理问号在右侧，与菜单栏图标同一行；中央避开实体摄像头，两侧分别按各自内容计算最小宽度，保持摄像头间隔不移动。收起高度等于摄像头所在的菜单栏区域，不在下方另加数字栏。普通屏最大 216 × 28 点，小屏收窄到 180 点。
- 收起时左侧显示周剩余额度，例如 `68%`，无 `left`；右侧显示绿色工作图标和数字，待审批／待输入时另加一个橙色 `?`。工作数只统计 `running`，等待状态仍在展开的 Active 列表中，完成数留在 Finished。展开后的额度卡片与进度条同样使用 `100 - used_percent`，剩余不超过 10% 时数字和进度条为橙色。原生 `used_percent` 的读取与存储保持不变，无读数或已过期时显示 `—`。
- 展开默认显示活动任务，保留完成列表入口；点击跳转 Codex 桌面对话或对应终端。
- 包含悬停预览、点击展开、Escape/外部点击收起、无数据、读取失败、跳转失败、退出和屏幕变化处理。
- 刘海默认跟随系统主显示器；**Settings → Notch & app → Notch display** 可选择跟随主屏或指定任意已连接屏幕。选择即时保存并同步到运行中的刘海；指定屏断开时临时回退主屏，重新连接后自动返回，不丢失偏好。切换窗口焦点不会移动刘海。
- 默认隐藏 Dock 图标；设置窗口中的 **Show in Dock** 开关即时保存，重新启动后继续生效。刘海打开的设置窗口共用一个可选 Dock 图标。
- macOS 仅接入 Codex；不加入其他代理、宠物、审批服务或主题编辑。

## 实现

- Rust 继续读取本地会话与额度；SwiftUI/AppKit 提供刘海、任务面板和系统跳转。
- Swift 原生层静态链接进主程序，使用同一个 `Agent Companion.app`；状态栏编辑器继续使用 Slint。
- app 使用 [`LSUIElement`](https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement) 避免启动时短暂出现 Dock 图标，运行中按偏好切换 AppKit activation policy。偏好保存在 `com.wxgopher.agent-companion` 的 `showDockIcon`，跨进程同步，不写入 Codex 配置。独立 CLI 编辑器也遵守该设置。
- Dock 图标为项目自绘的矢量图形，打包时生成全尺寸 ICNS 并随 app 完整性签名封装。
- 按 [AppKit 屏幕顺序](https://developer.apple.com/documentation/appkit/nsscreen/screens)将 `NSScreen.screens.first` 作为系统主屏。指定屏使用 `CGDisplayCreateUUIDFromDisplayID` 返回的稳定标识匹配；标识与名称作为单个 `notchDisplay` 字典保存在 `com.wxgopher.agent-companion` 偏好域，缺省表示跟随主屏，不写入 Codex 配置。设置通过分布式通知同步到刘海，显示参数、桌面空间和唤醒通知也会重新选择屏幕；设置列表每秒刷新并保留离线选择。同型号显示器使用稳定标识后缀区分。目标屏无摄像头时使用普通窄条；指定屏不可用时回退主屏，保留原选择。两种屏幕均以 `screen.frame.maxY` 贴住屏幕顶边，普通窄条覆盖菜单栏中央；顶部不使用扣除菜单栏后的 `visibleFrame.maxY`。展开只向下延伸，保持顶边和宽度不变；底部以 `visibleFrame.minY` 留出 Dock 空间。
- 悬停由跟踪区域与本地/全局鼠标移动事件共同驱动，并每 0.1 秒补查一次指针位置，覆盖菜单栏或屏幕边缘未送达鼠标事件的情况。可见窄条的判定区域左右各扩大 12 点、下方扩大 8 点，裁剪到当前所选屏幕范围并包含最顶边；摄像头高度内不超出可见侧栏边缘，避免触发相邻菜单图标。实际窗口和点击区域不扩大。只在实际进出边界时开始计时，忽略窗口重排产生的重复事件。停留约 0.18 秒展开、离开约 0.35 秒收起，不激活窗口或改变展开宽度。手动关闭后需移出再移入才重新展开。
- 原生刘海形状与窗口行为参考 Open Island `b50f87aa7d58af1478837d48909eb68baa37f9b9`，复用部分保留出处与 GPL 声明。
- 完成数沿用 Windows 的最近十五分钟会话窗口；有存活证据的长任务持续保留。读取持续失败超过 30 秒后，缓存不再视为当前存活证据，按事件时间正常过期。
- 首先完成 GUI 和可观测的本地状态；不通过启动新模型任务来刷新额度。

## 实机验收入口

1. 打开 app，MacBook 上确认剩余额度在摄像头左侧、工作数和待处理问号在右侧，与菜单栏图标同一行，中间不绘制文字；普通显示器窄条居中覆盖菜单栏、紧贴屏幕顶边。展开和收起时顶边与宽度不变。
2. 将鼠标顶到所选屏幕刘海中央的最顶边，或停在可见窄条左右 12 点、下方 8 点的容错区域（摄像头两侧的菜单区除外），应自动展开且不抢焦点；沿边缘移入展开面板应保持打开，移出后收起。点击展开后可用 Tab/Return 操作，Esc/外部点击收起；Esc 后鼠标未移开时不应立即重开。邻近菜单图标的点击行为不受容错区域影响。
3. 在 Codex 发起自己的正常任务，确认开始、需要输入、完成的变化；Active/Finished 切换和列表滚动正常。
4. 点击桌面任务返回同一个会话；点击 CLI 任务选中 Terminal/iTerm2 原标签页。拒绝 Automation 或关闭终端后显示错误与恢复命令。
5. 没有读数时显示 `—`；剩余额度应为 `100 - 原始周已用比例`，例如已用 90% 时窄条显示 `10%`、卡片显示 `10% left`，进度条保留 10%。用尽时窄条显示 `0%`；过重置时间后显示 `—`，等待新读数。
6. 点击 **Settings（设置）**，Apply 后关闭；刘海继续运行，再次点击不重复创建设置窗口。退出刘海后确认没有监控进程；单独启动 `codex-tui` 仍关闭即退出。
7. 在 **Settings → Notch & app → Notch display** 选择 **Follow primary display**，将外接显示器设为主屏，确认刘海移到外接主屏，展开保持同宽；把主屏改回内建屏、再改回外接屏，均应立即跟随。仅切换窗口焦点时不移动刘海。拔掉外接主屏后应回到系统剩余主屏，并按摄像头间隔重新计算窄侧栏，数字保持在菜单栏内；再插回时遵循 macOS 恢复的主屏设置与该屏尺寸。另检查桌面、全屏切换后的贴边位置与交互区域。
8. 默认启动和打开设置时均无 Dock 图标；在设置中用鼠标及 Tab/Space 切换 Dock 开关，应立即显示或隐藏且不打断窗口操作。开启后关闭设置仍保留一个图标；重启后记住选择。关闭开关后重启保持隐藏。单独启动编辑器，以及设置尚未关闭时退出刘海，也应遵守该偏好；不需要改动 Codex 配置或点击 Apply。

9. 在 **Notch display** 依次选择内置屏和外接屏，确认即时移动、各自菜单栏对齐、展开同宽，重新打开设置或重启 app 后仍保留选择。固定内置副屏时应保留摄像头两侧布局；仅更换系统主屏不移动固定屏幕的刘海。拔掉指定外接屏后应显示离线选项并临时回到主屏，重新连接后回到原指定屏。返回跟随模式后再次按系统主屏移动。用 Tab 和方向键检查下拉框操作，不点击 Apply 也应生效。
