# Windows TUI 提问通知

Codex 或 Dodex TUI 发起需要回答的问题，或通过已有 hooks 请求工具审批时，Agent Companion 会发送 Windows 通知。此功能只面向 Windows TUI，会话来源为桌面 App 时不会发送待回答通知。

在 **Settings → Taskbar & app → Question and approval notifications** 开启或关闭提醒，默认开启。它与任务完成通知分别设置。提问无需等待任务运行满 30 秒。

通知沿用任务完成通知的展示方式：静音弹出，3 秒后收起，尚未处理的问题保留在消息中心。同一问题不会重复提示；启动时已存在的旧问题、关闭提醒期间的问题和用户正在查看的问题不会在稍后补发。回答问题、结束任务、会话过期或关闭对应账号的监控后，会撤下对应的待回答通知。

普通 TUI 的提问从本机会话日志观察，不需要安装 hooks，也不会代替 TUI 回答。工具审批仍依赖已有的审批 hooks。通过 `agent-companion-codex` 启动的 TUI 继续支持现有提问卡片。

## 点击后的终端定位

点击通知后，Agent Companion 会检查该问题是否仍在等待，并尝试返回发起问题的终端。Codex 与 Dodex 的会话和通知分别归属各自账号。

- 通过 Companion 启动并成功记录位置的 Windows Terminal 会话，优先选择记录的标签页和分屏，包括后来切换到后台的标签页。
- 普通 TUI 没有上述记录时，尝试根据当前问题的文本匹配 Windows Terminal 暴露的 pane。只有唯一匹配时才切换焦点；同名项目、相同问题和已经关闭的 pane 不会被当作精确位置。
- 前台窗口里的其他分屏仍可收到提醒。正在查看 Companion 面板，或能确认正在查看发起问题的 pane 时，会抑制通知；缺少终端定位信息的普通 TUI 仍可能收到提醒。
- 无法确认具体 pane 时保留 Companion 的任务面板供查看。不会为这条通知新开恢复会话，也不会转去 Codex 桌面 App。

普通 TUI 的隐藏标签页可能没有可读取的 pane 文本；未记录位置的会话因此不能保证自动切换到隐藏标签页。窗口或终端关闭后也无法回到原 shell。

通知只展示经过长度限制的非保密问题预览，不展示工具审批命令、回答内容或标记为保密的问题正文。

## 开发验证（2026-10-22）

Windows 本地工作区回归共 512 次测试执行通过、8 项按条件忽略。多个测试二进制复用部分模块，执行次数不是独立用例总数。格式检查、全目标 Clippy（警告视为错误）及 Windows 优化构建通过。

新增回归覆盖连续及并行提问、原生请求与日志观察去重、回答后的通知清理、启动与关闭提醒期间不补发、Codex/Dodex 归属、同秒事件顺序、Windows 路径写法差异、保密内容、分屏唯一匹配及失效窗口。设置页的亮色、暗色渲染已检查。

真实 Windows 通知与终端焦点交互仍待手动验收：在其他应用或另一个分屏中等待提问，确认静音提醒与消息中心记录；点击后检查原 tab/pane 的焦点；在原 TUI 回答后确认提醒撤下。隐藏标签页和相同问题出现在多个 pane 的情形也需分别验证。
